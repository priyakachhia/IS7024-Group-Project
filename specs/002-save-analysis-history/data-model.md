# Data Model: Save Analysis History

## HistoryEntry

Represents one immutable saved analysis snapshot.

| Field | Type | Constraints | API role |
|---|---|---|---|
| Id | integer | Primary key, generated by storage | Returned response only |
| Neighborhood | string | Required, non-empty | Request and response |
| BusinessType | enum/string | Must be a supported business type | Request and response |
| PeriodStart | date | Required | Request and response |
| PeriodEnd | date | Required; not before PeriodStart | Request and response |
| CrimeCount | integer | Greater than or equal to zero | Request and response |
| PermitCount | integer | Greater than or equal to zero | Request and response |
| SafetyScore | decimal | Between 0 and 100 inclusive | Request and response |
| GrowthScore | decimal | Between 0 and 100 inclusive | Request and response |
| SuitabilityScore | integer | Between 0 and 100 inclusive | Request and response |
| SavedAt | date/time | Generated by the service; required | Response only |

## Relationships

History entries are standalone snapshots. There are no user-account relationships, editing relationships, or links to the Compare page in this feature.

## Validation and lifecycle

- The API validates all request fields before calling the service.
- `SavedAt` is assigned by the service at save time and is not accepted from the client.
- A valid request always inserts a new row; no uniqueness rule prevents duplicate analysis values.
- Invalid requests do not create rows.
- Reads order by `SavedAt` descending and return all entries as a JSON list.
- The database schema is created automatically on first application run.
